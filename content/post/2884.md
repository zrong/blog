经常用 ChatGPT/Codex 的朋友应该对这个状态非常熟悉：

![正在重新连接 5/5](/uploads/2026/fix-codex-reconnect-5-of-5-not-network-1.png)

一般情况下，我们首先会怀疑 Ladder：**魔法被打败了？**

## 魔法未败

然而，当我们把线路从 `北美->新加坡->日本` 全部切换一遍，而且发现其他网站都正常的时候，就不得不怀疑 Codex 本身了。

尤其是，这个问题经常出现在**自动压缩上下文**的时刻。胡扯 AI 群里也有朋友遇到过同类的问题。

直到有一次，我发现新的会话没问题，而老的会话无法连接，我于是对 GLM-5.3 问出这个问题：

> 为什么现在 Codex 有一个会话总是超时，但其他会话都正常？

![会话超时的原因](/uploads/2026/fix-codex-reconnect-5-of-5-not-network-2.png)

## 上下文爆炸了

所以要解决这个问题，只需要新开一个会话即可。

例如我会让 Codex 新开一个会话重读旧会话上下文，然后可能由于上下文过大，新开的会话会导致 Codex Crash。

然后我让 GLM-5.3 帮忙整理了一下迁移任务，再用这个 Markdown 接上任务即可。

![使用 GLM-5.3 帮忙整理的迁移任务](/uploads/2026/fix-codex-reconnect-5-of-5-not-network-3.png)

这个任务是一个生成图片的长程任务，大约生成了 60 张图片，然后调用局域网模型进行了抠图工作。大概是由于所有生成的图片都显示在了 Session 中，而这些图片又使用的是 Base64 输出，最终导致了上下文爆掉，而且无法压缩。

## 用子 Agent 解决问题

终极解决方案，是在 Codex 中调用生图任务时，要求它必须使用子 Agent，而且不要在主会话中贴图。我整理了一段内容，可以直接写入你的 `AGENTS.md`：

```markdown
## 生图与改图

- 所有图片生成、编辑与相关图像读取、视觉检查工作，必须交给子 agent 执行；主 agent 负责协调与汇总结果。
- 不得在主会话中展示或回传已生成、已修改的图片。仅提供图片的绝对访问路径，可使用普通 Markdown 文件链接，不得使用图片嵌入语法。
- 不得向主会话注入图片附件、内联预览、截图、Base64、data URL 或其他图像数据，避免上下文体积暴涨。
- 委派时必须明确要求子 agent：图像数据保留在其执行上下文中，最终仅返回产物路径和必要的简短文字状态，不得回传图像数据或触发展示。
- 如需读取或验证生成结果，由子 agent 完成；主 agent 不得为了复核而重新加载图片。
```

跑起来之后，你会发现会话中永远不会有图出现：

![子 Agent 生图](/uploads/2026/fix-codex-reconnect-5-of-5-not-network-4.png)

## 当前已经能原生生成透明图

gpt-image-2 的最新版本已经支持 `background: transparent` 参数的原生透明背景。

经过实测，Codex 内置的生图模型已经是最新版了，下面的提示词能让你 100% 生成原生 Alpha 透明图。

```text
Output a real transparent PNG with a clean native alpha channel. The transparent area must be actual alpha transparency, not painted pixels. No colored background, black background, white background, gray background, checkerboard, gradient, scene, floor, platform, cast shadow, halo or glow.
```
